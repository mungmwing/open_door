# 전투 소비 아이템·전용 에너지

몬스터·유물·소환·관전까지 포함한 최신 설치 순서는 [전투 확장 문서](combat-expansion.md)를 따릅니다. 아래 소비품 SQL 이후 몬스터 확장과 관전 SQL을 순서대로 적용합니다.

기존 Supabase 서버 판정과 방 버전 잠금을 확장하여 구현한다. 운영 DB에는 SQL을 실행하지 않는다.

## 구현 체크리스트

- [x] 카드·아이템 카탈로그·인벤토리·권한 구조 확인
- [x] 규칙 결정: 3슬롯, 사용 시 실제 1개 차감, 생성품은 전투 전용
- [x] 소비 아이템의 전투 효과 편집 및 저장
- [x] 로비 장착·해제, 실제 아이템 사용과 중복 차감 방지
- [x] 지정한 소비 아이템 목록에서 무작위 생성하는 카드 효과
- [x] 캐릭터별 전용 에너지 이름·시작량·최대량·턴 회복 설정
- [x] 전용 에너지 획득 효과·카드 비용·전투 표시
- [x] 원본 인벤토리 동시 수정/오래된 관리자 저장 보호
- [x] 수동 적용 SQL과 설치 순서 제공
- [x] SQL 통합 검증·빌드·브라우저 QA

## 적용 규칙

- 각 캐릭터의 전투 인벤토리는 3칸. 원본 소비 아이템은 로비에서만 장착/해제한다. 같은 아이템도 보유 수량 내에서 여러 칸에 장착할 수 있다.
- 장착은 예약/차감이 아니다. 사용 시 서버가 소유권과 잔여 수량을 다시 확인하고 효과 판정과 1개 차감을 하나의 트랜잭션으로 처리한다. 사용 실패, 중복 요청, 잘못된 대상에는 소모하지 않는다.
- 생성 효과는 관리자가 지정한 소비 아이템 목록에서 균등 무작위로 뽑는다. 빈 칸만 채우고 가득 차면 초과 생성은 건너뛴다. 생성품 사용·버리기는 원본 인벤토리에 영향을 주지 않는다.
- 소비 아이템 효과는 아이템 관리에서 설정한다. 전투 시작 시 참조 카탈로그를 복사하여 진행 중 편집에 영향을 받지 않는다. 생성 아이템은 다른 아이템을 다시 생성할 수 없다.
- 전용 에너지는 이름을 비우면 비활성화. 기본 에너지와 별도이며 전투에만 존재한다. 시작량·최대량·턴 회복량을 설정하고, 턴 초기화 여부를 선택한다. 기본은 턴 간 유지, 매 전투 시작량부터 시작한다.
- 카드 비용은 사용 효과 전에 차감한다. 자신의 사용 효과로 같은 카드의 부족한 비용을 먼저 충당할 수 없다.

## 수동 적용 순서

운영 DB에는 실행하지 않았습니다. 기존 전투와 카드 사전 설정 SQL을 이미 적용했다면 **supabase/queries/add_combat_consumables_energy.sql 전체만** Supabase SQL Editor에서 직접 실행합니다.

처음 전투 기능을 설치하는 기존 TRPG 프로젝트에서는 다음 순서입니다.

1. create_realtime_combat.sql
2. add_card_combat_presets.sql
3. add_combat_consumables_energy.sql

소비품 확장 SQL에는 키워드 수정도 포함됩니다. 예전 fix_combat_card_keywords.sql이나 기본 전투 SQL을 다시 실행하면 방 액션 함수가 이전 기능으로 교체될 수 있습니다. 그 경우 소비품 → 몬스터·유물 → 관전 SQL 순서로 다시 적용합니다. SQL은 트랜잭션으로 감싸며 재적용 검증을 마쳤습니다.

추가 컬럼: characters.personal_energy, characters.inventory_version, items.combat_effects. 인벤토리 변경 번호 트리거, 관리자 저장 RPC, 소비품 조회 RPC 및 서버 전투 판정을 추가/교체합니다. 기존 보유 수량을 일괄 변경하지 않습니다. 진행 중 방의 데이터를 보정하지 않으므로 적용 후 새 방을 사용합니다.

## 설정 방법

1. **관리자 → 아이템 관리**: 타입을 소비로 설정하고 ‘전투에서 사용할 때’에 사용 효과를 추가한 뒤 저장합니다. 자유 형식 설명만 입력한 아이템은 장착 후보에서 비활성화됩니다.
2. **캐릭터 관리 → 기본·전투 정보**: 전용 개인 에너지에 명칭, 시작량, 최대량, 매 턴 회복량과 초기화 여부를 설정합니다. 명칭을 비우면 사용하지 않습니다.
3. **같은 캐릭터의 카드 탭**: ‘전용 에너지 획득’ 효과와 별도의 사용 비용을 설정합니다. ‘무작위 소비 아이템 생성’ 효과에서는 후보 체크박스와 생성 수량(1~3)을 설정합니다. 전체 변경사항을 저장합니다.
4. **플레이어 → 전투 로비**: 자신의 아이템을 최대 3칸에 선택하고 ‘소비 아이템 장착 저장’을 누른 뒤 준비 완료합니다. 장착을 바꾸면 준비 상태가 해제됩니다.
5. **전투 중**: 아이템 사용 버튼을 누릅니다. 적/아군 선택이 필요한 아이템은 먼저 대상을 지정합니다. 생성품에는 ‘전투 전용’ 표기와 버리기 버튼이 표시됩니다.

## QA 결과 (2026-09-12)

- 기존 전투·키워드·저장 회귀 검증: node scripts/combat-qa.mjs — 66개 통과.
- 확장 SQL·권한·아이템 소모·생성·에너지·저장 검증: node scripts/combat-resources-qa.mjs — 32개 통과. 로컬 PGlite에서 실제 SQL과 authenticated/anon 역할로 실행했습니다.
- 중복 요청, 남의 아이템, 보유량 초과, 턴/방 종료, 여러 방의 동일 재고 사용, 오래된 관리자 저장을 거부합니다. 효과 오류를 주입하여 차감 이후 오류도 재고·슬롯·방 상태가 모두 롤백되는 것을 확인했습니다.
- 생성품 3칸 상한, 후보 제한, 원본 불변, 생성품 버리기, 전투 시작 후 카탈로그 편집과 스냅샷 분리를 확인했습니다.
- 기본/개인 비용 별도 차감, 비용 부족 시 상태 보존, 턴 유지/초기화, 최대량, 자원 없는 아군 제외를 확인했습니다.
- 확장 미적용 시 새 기능은 저장 전에 안내하며, 통신·권한 오류는 SQL 미적용 오류와 구분합니다.
- 브라우저: 실제 AdminItemsPage, AdminCharacterWorkspace, CombatPage를 로컬 임시 DB와 연결하여 설정 저장·재조회 → 3칸 장착 → 전투 시작 → 아이템·카드 사용까지 검증했습니다. 운영 데이터에는 접근하지 않는 QA 어댑터를 사용했습니다.
- 실제 화면 결과: 회복약 사용으로 HP 30→42, 원본 3→2; 카드 사용으로 기본 에너지 3→2, 투지 2→4, 빈 슬롯에 생성품 1개; 생성 회복약 사용으로 HP 42→50, 원본 2개 유지. 관리자 화면도 폴링으로 반영되었습니다.
- 모바일 전투: 390px에서 소비품 슬롯을 세로로 표시하고 가로 넘침 없이 사용 가능. 데스크톱 카드 편집에서 후보 목록, 맞춤 비용명, 도움말을 확인했습니다. QA 탭의 브라우저 오류 로그 0개.
- npm run build 성공. 새 컴파일 경고 없음; 기존 500KB 번들 크기 경고만 있습니다. git diff --check 통과.
