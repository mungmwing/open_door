# 게시물 로딩 오류 수정

대상: `http://localhost:4001/#post/b352d7d4-882b-4119-80a4-98f72a043c25` — 「ai로 캐릭터 샤샥」.

## 확인한 원인

본문은 9,382,862자이며 큰 base64 이미지 3개를 포함한다. 브라우저에서 Marked의 블록 정규식 처리 중 `RangeError: Maximum call stack size exceeded`가 발생했다. 기존 로더는 렌더링 예외를 정리하지 않아 로딩 표시가 계속 남았다. 게시물 부재나 접근 권한 오류는 아니었다.

## 수정

- `src/lib/postRendering.js`: 이미지 data URL을 짧은 임시 토큰으로 바꾼 뒤 Markdown을 파싱하고 원래 URL을 복원한다. 복원한 HTML 전체를 기존 DOMPurify로 정제한다. 원본 DB 본문은 바꾸지 않는다.
- 파서 오류에는 이스케이프한 원문을 표시한다.
- 게시물 로더에 예외 처리·20초 요청 중단·로딩 해제·재시도 UI를 추가했다. 이전 화면의 늦은 응답은 현재 게시물을 덮어쓰지 않는다.
- 선택적 프로필 장식 조회 실패는 본문 표시를 막지 않으며 좋아요/댓글·조회수 처리는 본문 표시 뒤에 실행한다.

## 검증

- 합성 대형 이미지, 토큰 충돌, 코드 블록, 파서 실패, 최종 정제 경로, 실제 본문 테스트 6개 통과.
- 실제 브라우저에서 제목과 본문 이미지 3장이 정상 표시됐다. 이미지 원본 너비는 각각 1254, 1254, 1672px이며 로딩 표시가 해제됐다.
- 게시물 수정은 추가 SQL 없이 적용된다. 본문의 이미지 데이터 크기 자체는 유지되므로 다운로드 양은 기존과 같다.
